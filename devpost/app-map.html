🗺️ ErrorSpeak — Application Map

Code Tour, Architectural Stops, and a Practice to Reuse

⚡ What ErrorSpeak Does

ErrorSpeak is a browser-only React app that turns a pasted or sample terminal error into a structured triage report: environment, error type, severity, the exact fault line, a plain-English explanation and a suggested fix. A local rule-based engine (Python, Node.js, Git, Docker, CORS, Shell) handles the diagnosis offline, states its own confidence, and says so honestly when no rule matches. Every report, whether from the local rules or from a connected LLM, is run through an evidence check (are the claims actually in the trace?) and a command safety check (is the fix command destructive?) before the user sees it. Connecting an LLM is optional and works with any provider the user chooses — Anthropic, OpenAI, Gemini, OpenRouter, Groq, or a custom OpenAI-compatible server; it redacts secrets first, and shows the user exactly what will be sent.

🔄 Data & Execution Flow

The local path (steps 1–3) always runs and never leaves the browser. Step 4 only runs if the user has connected a model (any provider) and clicks "Ask <model>"; its answer goes back through the same checks in step 3.

📍 Code Tour

Stop 1 • Entry Point
Terminal Editor & App Coordinator
src/components/TerminalInput.jsx & src/App.jsx

The monospace editor captures pasted text or a preset click and shows the live environment badge. App.jsx holds the app's state (input, reports, AI status, LLM connection config) and calls parseError(text) on "Run Triage Engine" or Ctrl+Enter.

Stop 2 • The Triage Kernel
Deterministic, Honest Parser
src/engine/parser.js

detectEnvironment() and parseError() turn the raw trace into a structured TriageReport: the innermost Python frame, the first non-internal Node frame, real pip/npm package names, severity, confidence and a fixKind of "shell", "code" or "diagnose". When nothing matches, it returns low confidence and no fix instead of guessing.

Stop 3 • Checks Before Trust
Evidence Check and Command Safety, Rendered in the Card
src/engine/grounding.js & src/engine/safety.js, used by src/components/TriageCard.jsx

TriageCard.jsx calls groundReport(report, rawText) to match each claim (error type, location, quoted code, package name) against the original trace, and lintCommand(fixCommand) to rate the fix safe, caution or danger. The card shows "N/N claims found in your trace", the safety banner, and opens the evidence list automatically when something isn't verified.

Stop 4 • The Optional Second Opinion
Redaction and the Connect-Any-LLM Dispatcher
src/engine/redact.js & src/engine/claude.js, via src/components/AIPanel.jsx

AIPanel.jsx runs redactSecrets(rawText) and shows what will be hidden, with a preview. On "Ask <model>", App.jsx lazy-loads engine/llm.js, which calls detectProvider() (from engine/providers.js) to route Anthropic to engine/claude.js (the Anthropic SDK with a zod schema) or any other provider to its own OpenAI-compatible request. Either path returns a TriageReport with source: "ai", a provider, a model, and verbatim evidence quotes, so it goes through Stop 3's checks exactly like a local report.

🛠️ To Change This, Start Here

  • To add a new sample error: add an entry to ERROR_PRESETS in src/engine/presets.js (raw text only; it runs through the real parser).
  • To change triage logic for an environment: edit the matching function in src/engine/parser.js (e.g. parsePython, parseNode, parseGit, parseDocker, parseCors, parseShell).
  • To change what counts as evidence: edit groundReport() in src/engine/grounding.js.
  • To change what counts as a dangerous or risky command: edit the DANGER / CAUTION rule lists in src/engine/safety.js.
  • To change what gets redacted before an AI request: edit the RULES list in src/engine/redact.js.
  • To add or change a provider: edit PROVIDERS and detectProvider() in src/engine/providers.js.
  • To change the shared prompt, JSON schema, or report shape: src/engine/triage-schema.js (used by both claude.js and llm.js).
  • To change Anthropic-specific request behavior (effort, fallback models): the SUPPORTS_EFFORT / SUPPORTS_FALLBACK patterns in src/engine/claude.js.
  • To change how non-Anthropic providers are called: src/engine/llm.js.
  • To verify a change: add or update an assertion in src/engine/test-parser.js and run npm test.

💡 A Practice to Reuse

Verify instead of trust: whenever an app (rule-based or AI-powered) produces a confident-sounding diagnosis, don't just render it — check it against the source material first, and show the user which claims passed and which didn't. In ErrorSpeak, grounding.js does this for every report regardless of whether it came from the local parser or from whichever LLM the user connected, so an invented file name, package or quote gets flagged "not found" instead of being presented as fact. The same pattern (local engine first, any LLM as a fallback behind one shared schema, and a check that runs on both) transfers to any tool that mixes deterministic logic with an LLM call.
