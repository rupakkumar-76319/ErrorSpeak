📐 ErrorSpeak — Product Requirements

A local-first developer triage tool that turns opaque terminal errors into plain-English explanations, the exact fault line, and fixes that are evidence-checked and safety-checked before the user copies them.

🚀 The Core Journey

Step 1
Arrival
A dark developer console with an input editor and a tray of 7 sample errors (Python, Node.js, Git, Docker, CORS, a Postgres error that leaks a password, and a Rust error the local rules don't cover).
Step 2
Error Ingestion
Click a sample or paste your own terminal output. The environment badge updates as you type.
Step 3
Local Triage
Detects the environment, extracts error type and innermost fault location, scores severity (1-10) and reports confidence (high, medium, low).
Step 4
Inspection
Provenance strip, plain English with TL;DR toggle, where it broke, the fix with safety rating, suggested patch, and evidence check.
Step 5
Second Opinion
The AI panel previews the redacted text; the connected model's structured report is checked the same way as the local one.
Step 6
Outcome
Copy the command (confetti only for non-destructive commands) and fix the error.

⚙️ Features and Behavior

Error Ingestion & Detection

The user can paste any text into the editor or click a sample. Samples go through the same parser as pasted text; there are no canned answers.

✓ Typing or pasting updates the environment badge immediately.
✓ Clicking a sample fills the editor and runs triage without a page reload.

Local Triage Engine

Produces a structured report (environment, errorType, severity, location, offendingCode, plainExplanation, rootCause, fixKind, fixCommand, whyItWorks, fixDiff, confidence). Uses the innermost Python frame, the first non-internal Node frame, real package names (e.g. cv2 → opencv-python, @scope/pkg/sub → @scope/pkg), and the container, origin and branch names from the trace. When no rule matches, it says so instead of guessing.

✓ All 7 samples produce the expected error type, location and fix (npm test).
✓ Unrecognized input shows low confidence and points to the AI panel.

Evidence Check

Matches the error type, file and line, quoted code, installed package names, and the connected model's evidence quotes against the raw trace.

✓ The card shows "N/N claims found in your trace".
✓ An invented file, package or quote is marked "not found" (covered by tests).

Command Safety Check

Rates every suggested command as safe, caution or danger, with reasons.

✓ rm -rf, git reset --hard, force pushes, curl | sh and docker system prune are flagged as destructive, and the copy button becomes "Copy anyway".
✓ Placeholders, sudo, --force and --legacy-peer-deps are flagged as caution.

Connect Any LLM (optional)

The user enters a model name and an API key; the provider is detected from the key prefix (sk-ant- Anthropic, sk-or- OpenRouter, gsk_ Groq, AIza Google Gemini, sk- OpenAI) or, if a base URL is set under Advanced, treated as a custom OpenAI-compatible server (key optional, e.g. a local Ollama instance). Settings are stored only in this browser. Redacts API keys, tokens, JWTs, private keys, connection-string passwords, secret assignments, emails and user-folder names before sending; the user can preview the exact text. Anthropic is called through its SDK with a zod structured-output schema; every other provider is called as an OpenAI-compatible endpoint with the schema spelled out in the prompt, then validated.

✓ Without a model connected, the panel offers "Connect an LLM to enable" and the app works fully offline.
✓ The Postgres sample shows 2 sensitive items hidden, and the preview contains no password or user name.
✓ The AI report shows a violet "<provider> · <model>" badge and goes through the evidence and safety checks.
✓ API errors (bad key, rate limit, model/endpoint not found, network or CORS failure, invalid or wrong-shaped JSON) are shown in the panel and the local diagnosis stays visible.

🛡️ States and Boundaries

  • Empty State: prompt to paste an error or pick a sample, with the Trace / Explain / Fix safely steps.
  • Analyzing: a short scan state on the run button.
  • Results: triage card plus AI panel.
  • Low Confidence: "No reliable fix from the local rules", and the AI panel is highlighted.
  • AI Loading / Error: spinner on the button; readable error message in the panel.

🧭 Product Decisions

  • Local-first, AI second: most beginner errors follow known patterns, so they are answered instantly, offline and free; the AI is used where it adds value.
  • Verify instead of trust: AI answers and rule answers are both checked against the trace, because a confident wrong answer is the main risk for beginners.
  • Bring-your-own key and model, no backend: nothing passes through a server we run, and the user decides which provider to use and what is sent.
  • Single surface layout: the whole loop fits on one screen and in a short demo video.
